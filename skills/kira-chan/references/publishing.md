# 제작 결과 발행

## 어디에 발행하는가

설치한 사람의 저장소와 계정을 사용한다. `aihubos/kira-chan`은 원본과 공개 예시이며 설치만으로 이곳의 쓰기 권한이 생기지 않는다. 발행처가 없으면 원고·이미지·문구를 먼저 완성하고 사용할 저장소 또는 업로드할 곳을 확인한다. 이미 지정·승인된 발행처는 다시 승인받지 않는다.

로컬 저장, 웹 공개, 메신저 전송, 예약 등록은 서로 다른 결과다. 완료된 단계와 남은 단계를 구분한다.

## GitHub Pages로 발행

처음 이용하는 사람은 [원본 저장소](https://github.com/aihubos/kira-chan)를 자신의 계정으로 Fork할 수 있다. Fork는 기존 발행본도 함께 복사한다. 기존 자료를 보존하고 새 날짜의 본인 발행본을 추가한다. 저장소 Settings → Pages에서 사용할 브랜치의 루트(`/`)를 선택한다. 원본은 `main`을 사용하지만 본인의 설정을 실제로 확인한다.

도구로 게시할 수 있다면 다음 순서로 진행한다. 웹만 사용할 수 있다면 ChatGPT가 만든 파일을 다운로드한 뒤 GitHub의 Add file → Upload files로 동일한 폴더 구조를 업로드한다.

1. 대상 저장소의 기존 변경과 Pages 주소를 확인한다. 코드를 수정하기 전 가장 최근 날짜의 `index.html`, 경제판 `economy/index.html`, 루트 `reader.css`와 `card-frame.css`를 읽고 재사용한다. 확인된 예시는 [2026-09-20 AI 뷰어](https://github.com/aihubos/kira-chan/blob/main/2026-09-20/index.html)다. 예시 기사·날짜·주소는 새 발행본에 남기지 않는다.
2. AI판은 `YYYY-MM-DD/index.html`, 경제판은 `YYYY-MM-DD/economy/index.html`에 새 페이지를 만든다. 각 폴더에 해당 판의 `sources.md`를 둔다. 카드 경로는 아래 표를 따른다. 기존 날짜가 있으면 새 수정판 경로를 정하고 기존 내용을 보존한다.
3. 제목·날짜·요일·설명·이미지 파일명·Threads 문구·출처를 이번 호로 바꾼다. `pageURL`, Open Graph URL·이미지 주소, 공유용 텍스트의 URL을 **본인의 실제 Pages 주소**로 바꾼다. AI 페이지의 상대 경로는 `../assets/`, 경제 페이지는 `../../assets/`다. 공통 CSS 상대 경로도 각각 `../`, `../../`로 연결한다.
4. 루트 홈은 한국시간 오늘의 두 판을 찾는 고정 홈으로 유지한다. 날짜별 뷰어로 덮어쓰지 않는다. 오늘 발행본이 없으면 준비 중으로 표시되는 것이 정상이며, 과거 발행본은 날짜 주소로 연다. 주제판은 `topics/<주제명>/index.html` 같은 별도 주소로 전달하고 데일리 홈에 억지로 끼워 넣지 않는다.
5. 카드 전체가 잘리지 않는 화면 높이 고정 뷰어, 좌우 한 장 이동, 기본 닫힘 Threads 메뉴, 카카오톡 공유를 보존한다. 공유창을 띄운 것만으로 실제 발송됐다고 말하지 않는다.
6. 해당 발행 파일만 업로드/커밋한다. 비밀 설정, 전송 스크립트, 수신자 정보, 실행 로그는 포함하지 않는다. 두 판 동시 발행 요청이면 두 판이 준비된 뒤 한 번에 게시한다.
7. Pages 배포가 완료된 뒤 공개 주소에서 날짜·판·이미지 10개·출처 링크를 실제로 확인한다. 공개 확인이 불가능하면 ‘업로드 완료, 공개 확인 대기’로 보고한다. 이전 발행본도 보존됐는지 확인한다.

| 판 | 이미지 경로와 파일명 |
|---|---|
| AI | `assets/YYYY-MM-DD/YYYY-MM-DD_카드뉴스_01.png` ~ `10.png` |
| 경제 | `assets/YYYY-MM-DD/economy/YYYY-MM-DD_경제시사_카드뉴스_01.png` ~ `10.png` |

ChatGPT 웹 프로젝트는 저장소를 자동 설치·실행하는 환경으로 가정하지 않는다. 이미지 생성·파일 생성·연결 앱 지원 여부를 확인한다. 게시 권한이나 GitHub 쓰기 도구가 없다면 이미지·문구·HTML을 제공하고 위 수동 업로드 안내를 함께 전달한다. 지침만 넣어 놓고 자동 발행이 연결됐다고 말하지 않는다.

## 반복 발행·메신저

사용자가 요청한 경우에만 예약이나 전송을 설정한다. 날짜·종류·시간대·수신자·발행처를 정하고 해당 환경의 실제 예약/전송 도구를 사용한다. 설치 명령만으로 매일 발행을 예약하지 않는다.

전송은 이미지 앨범과 요약·링크로 구성할 수 있다. 성공 응답과 실제 전송시각을 비공개 작업 기록에 남기고 성공 항목을 중복 전송하지 않는다. 타임아웃으로 수락 여부가 불명확하면 자동 재전송하지 않는다. API 수락과 수신자의 읽음을 구분한다. 계정 비밀이나 수신자 정보를 공개 저장소·공유 프로젝트에 저장하지 않는다.
